# Ox Content移行パイロットの結果

後続の[コンポーネント移植後のOx単独SSG・Astro比較](../REPORT.md)を追加した。以下はNuxtを残す構成とOx標準テーマを比較した最初の検証記録。

2026年10月30日、ローカルの `1172292` を基準に検証。

**4ページはNuxtを残す2案で従来の表示に一致させられた。ただし、今回の範囲ではSSGの高速化は確認できなかった。** 次の検証ではナビゲーションと前後リンクの取得もOxに移し、Nuxt Contentの全件キャッシュ生成を外せる構成を試すことを提案する。

## 結果の比較

| 構成 | VRT | SSG全体の中央値 | 判断 |
| --- | --- | ---: | --- |
| 従来のNuxt Content v2 | 16/16成功・20画像一致 | 43.75秒 | 基準 |
| Nuxt維持、クエリのみOx | 16/16成功・20画像一致 | 44.00秒 | 互換性上の移行候補。これだけでは速度改善なし |
| Nuxt維持、本文パーサーもOx | 16/16成功・20画像一致 | 43.74秒 | 対象4ページでは互換化可能。追加の互換処理と保守が必要 |
| Nuxtを外し、Ox自身の標準SSG | 16/16で画像差分を検出 | 同等機能でないため比較対象外 | 既存テーマ・操作機能の移植が必要 |

VRTは1440×900 / 390×844とlight/darkの組み合わせ。PNG復号後の全RGBAバイトを比較し、アンチエイリアスも含め許容差分を0にした。モバイルのメニューと目次を開く状態も含む。リンク、見出しID、画像alt、コード、SEO情報、クライアント側のページ遷移、hydrationエラーも検証した。

対象は日本語のノート、ハッシュタグ、プラグイン作成と、英語のノート。通常のMarkdown、MDC注記、HTMLの表、画像、AiScript、翻訳案内をカバーした。詳細な条件と対象外の機能は [README](./README.md) を参照。

## 時間の評価

各構成を3回、順番を入れ替えて計測した。毎回 `.nuxt` と対象の生成先を削除した。Crowdin APIを無効化し、VRTやブラウザーを並行実行せず、同じ4ページと必要な静的データを生成した。Node 22.22.2 / macOS arm64 / Apple M1 Pro。

| 構成 | 全体の範囲 | プリレンダー中央値 | Content全件キャッシュ生成の中央値 |
| --- | ---: | ---: | ---: |
| 従来 | 42.96–43.86秒 | 24.68秒 | 18.35秒 |
| クエリのみOx | 43.72–44.67秒 | 24.61秒 | 18.41秒 |
| 本文パーサーもOx | 42.32–44.98秒 | 24.62秒 | 18.41秒 |

全体の差は実行間のばらつきに収まっている。ここから高速化率を主張する根拠は得られない。

Nuxt Content v2の `/api/_content/cache.<build>.json` の生成だけで、今回のビルド全体の約42%を占める。4ページの本文取得をOxに移しても、この全件処理は残る。また、レイアウトの `fetchContentNavigation` と `DocsPrevNext` の `findSurround` は引き続きNuxt Contentに依存している。

参照記事はNuxt Content v3 / D1からの取得経路を置き換えた事例。このサイトのv2構成には同じDB経路がなく、記事で報告されている速度向上をそのまま期待することはできない。[参照記事](https://zenn.dev/ytr0903/articles/582133c77daa4e)

これは**全サイトのSSG時間ではない**。全ページのクロールと旧URLリダイレクト生成は対象外であり、今回の値から本番全体の短縮率を推定しない。Ox標準SSGの単独実行は機能が異なるため、その処理時間を速度向上の根拠に使わない。

## 互換化で必要になった処理

クエリ案では、Oxの公式コレクション生成APIが作る `queryCollection` をNitroに接続し、既存のMDCパーサーとVueレンダラーを維持した。静的ホスティング上のページ遷移に必要な本文JSONも、パスごとに生成した。

本文パーサー案では、OxのHTMLをHAST経由でMDC互換ASTに変換し、既存のVueコンポーネントで描画した。tip/warning、見出しIDとTOC、外部リンク属性、`.md` 相対リンク、英文の空白補正、画像altを合わせる処理が必要だった。AiScriptを含むコードは既存Shikiに渡して配色とDOMを維持した。コードを段落内に入れるとHTMLの解釈が変わりhydrationに失敗するため、ブロックとして挿入した。

このアダプターは対象4ページ向け。MDCの全構文、独自frontmatter、YAMLのステップガイド、ディレクトリ索引、ブログ、全言語を移行できることを証明するものではない。特に4ファイルには独自YAML frontmatterがなく、クエリ案をそのようなページへ広げる前に、Oxメタデータの結合と追加の比較ケースが必要。

Ox 3.4.0のViteプラグインはVite 8をpeer dependencyに持つ。このサイトのVite 7を更新する範囲には広げず、コレクション生成APIとNitroのaliasを使った。MDCの内部コンパイラーやTOC生成器に依存する部分は、依存更新時の再検証が必要。

## 提案

最初の本番移行候補は、**Nuxtと既存MDC描画を維持する構成**とする。今回のクエリ置換のみを本番に入れても、SSG高速化の効果は見込めると確認できていないため、先に以下を同じ4ページで追加検証するのが妥当。

1. Oxのメタデータで、サイドバーと前後リンクを生成する。数値プレフィックスの並び順、`_dir.yml`、非表示項目、言語のフォールバックを従来と比較する。
2. 本文描画を `@nuxtjs/mdc` の直接利用に切り出し、パイロット構成でNuxt Contentの全件キャッシュ生成・クエリ経路を外す。原稿は既存のまま使う。
3. 20画像の一致とリンク・操作検証を維持しながら、同条件でSSG時間を再計測する。独自frontmatterやステップガイドを含むページを検証対象に追加する。
4. 短縮効果と互換性が確認できた段階で、全サイトSSGの計測と移行範囲を決める。

本文パーサーのOx化は、この段階の計測でMarkdown変換が残るボトルネックと判明した場合に検討する。今回だけでも互換アダプターが必要になっており、速度改善がない状態で保守範囲を増やす利点は小さい。

OxがSSGまで担当する案では、Misskey固有のVueテーマ、i18n、目次、ナビゲーション、テーマ切り替え等の移植が必要になる。今回の標準テーマは全条件で従来との差分が出ているため、「表示を維持しながらSSGを高速化する」最初の移行案としては推奨しない。
