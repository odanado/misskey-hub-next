# VizeによるVueコンパイラ置換の検証

全公開1,991 URLでの追加ベンチマークは[FULL_SSG_REPORT.md](./FULL_SSG_REPORT.md)を参照。以下は4ページでの過去のVRT・速度比較。

2026年10月30日。前回と同じ4ページで、Nuxt・Ox単独・Astro＋MDC・Astro＋OxのVue SFCコンパイラをVize 0.607.0へ置き換えて検証した。本番コンポーネント・通常ビルドは変更せず、環境変数で実験時だけ切り替える。

設定上の制約・出力不具合・連携上の問題の詳細と最小再現は、[独立した問題レポート](./VIZE_ISSUES.md)にまとめた。

## 結果

| 構成 | 通常Vue・中央値（最小–最大） | Vize・中央値（最小–最大） | 中央値の変化 |
| --- | ---: | ---: | ---: |
| Nuxt＋Content v2 | **41.93秒**（41.88–42.16） | **46.72秒**（46.70–50.28） | **11.4%増加**・約4.78秒 |
| Ox単独SSG＋移植Vueテーマ | **4.21秒**（3.75–4.28） | **3.44秒**（3.36–3.47） | **18.3%短縮**・約0.77秒 |
| Astro＋既存MDC | **5.02秒**（4.54–5.09） | **4.42秒**（4.34–4.55） | **11.9%短縮**・約0.60秒 |
| Astro＋Ox Content | **4.59秒**（4.55–4.61） | **4.34秒**（4.26–4.42） | **5.3%短縮**・約0.24秒 |

全値は今回の各3回から算出した。前回の構成比較とは測定回が異なるため、コンパイラの効果はこの表の左右で比較する。通常VueのOx・Astroには約0.5秒のばらつきがあり、短縮率を全環境での保証とは扱わない。

**移植3案ではVizeをSSG高速化の候補にできる。Nuxtでは今回の設定で高速化の効果はなかった。** NuxtはContentの全件キャッシュに両者とも約17–18秒かかり、Vize化後もこの処理が残る。Nuxt連携やSSR・バンドルを含む時間が増えており、この結果だけでSFCコンパイラ単体の速度を評価しない。

Vizeを使った場合のAstroへのOx追加は **4.42秒→4.34秒、約0.08秒・1.8%短縮**。Vize化を考慮しても、今回の4ページではOx追加の効果は小さい。

速度だけを優先すれば **Ox単独＋Vizeの3.44秒**が最速。移行・保守を含むAstro＋既存MDCの提案は維持し、Vizeは追加の高速化候補とする。ただし下記の互換修正を持つため、本番全ページへそのまま適用できるという結論ではない。NuxtへのVize導入は今回の目的では見送るのが妥当。

## 表示・操作の確認

**全8条件で各16テストが成功し、合計128/128成功。各20画像、合計160画像が元のNuxt基準とRGBA完全一致した。** Vizeの4条件だけでも80画像の完全一致を確認している。

4ページ×PC / モバイル×light / darkの16テストに加え、モバイルのメニュー・目次を開いた画像も比較した。マスクや許容ピクセル差はなく、基準画像も更新していない。リンク先・属性、見出し、SEO、画像alt、コード本文、hydration、ページ遷移、デスクトップのテーマ切り替えと保存も検証した。

全構成で外部通信を同様にブロックし、ローカル画像・フォント・hydrationを待って比較した。GitHub ActionsにもVize構成を追加したが、ここで報告するのはローカルでの実測・検証結果。

## 計測方法

通常Vue版とVize版の計8条件を同じ環境で各3回、計24サンプルを採用する。構成の順番を巡回し、コンパイラの順番も交互にする。ビルドとブラウザー検証は同時実行しない。過去の計測値を通常版の比較対象として流用しない。

計測用ラッパー自身の起動を除き、実ビルド子プロセスの起動・ライブラリ初期化・コンテンツ取得・Vueコンパイル・SSR・JS/CSS/HTML生成・公開アセットのコピーを含む。Nuxtの `.nuxt`、各構成の生成先とキャッシュは毎回削除する。Vizeは `scanPatterns: []` で到達したSFCを新しいプロセスでコンパイルし、一括コンパイルのディスクキャッシュを利用しない。OSのファイルキャッシュは消さない。

Node 22.22.2 / Apple M1 Pro / macOS arm64。Vue 3.5.25、Nuxt 3.20.2、Astro 6.4.8、Ox 3.4.0、MDC 0.9.5、Shiki 1.29.2、UnoCSS 66.5.12、Playwright 1.58.2。Vize追加前の既存ルート依存・package・snapshot定義はすべて維持し、新しい実験用依存だけ追加した。

この値は4ページのSSG全体の時間であり、SFCコンパイラ単体のベンチマークではない。SVGのVueコンポーネント化は既存の `vite-svg-loader`、本文は各原稿エンジンの処理を維持しており、それらをVizeへ置き換える検証ではない。Nuxtは既存アプリ全体のコンパイル・Content全件本文キャッシュを含み、移植3案は4ページ用アプリのコンパイルと本文変換に限定する。各構成内でコンパイラだけを比較するための測定であり、全サイト移行後の絶対時間へ外挿しない。

## 連携方法と必要な互換修正

- **Nuxt**: 公式 `@vizejs/nuxt` のネイティブコンパイラと自動import・コンポーネントbridgeを使う。lint生成は無効。既存 `isCustomElement` 関数を残すと公式モジュールが標準コンパイラへ戻るため、パイロット時だけ同等の `customElements: ['model-viewer*']` に置換した。Vite 7には `parseSync` exportがなく追加i18n bridgeが失敗するため、そのbridgeだけ無効とし既存vue-i18nのグローバル機能を維持する。
- **Ox単独**: クライアントとSSRの両方のVite VueプラグインをVizeへ置換する。Nuxt境界の自動importはVizeの生成JSへ注入する。
- **Astro 2案**: 公式Vue integrationのSSR・island・appEntrypointを維持し、SFCコンパイラをVizeへ置換する。本文エンジンはMDC / Oxのまま。

全Vizeビルドでネイティブプラグインの登録を検査し、標準コンパイラへの意図しないフォールバックを防いだ。初期調査ではNuxtのフォールバックが発生したが、その探索計測は最終比較に含めていない。

Vize 0.607.0では、スロット内の `template v-else` でSSRのFragmentマーカーが不足し、ブラウザー側と不一致になった。さらにVizeのVite向けCSS処理で `@screen lg` 内のセレクターのスコープが失われ、UnoCSSによる展開後も優先度が変わってPCの文書レイアウトが崩れた。追加の最小再現では、SFC単独コンパイルとVite向けCSS APIで結果が異なることを確認している。

そこで `vize-compat.mjs` が毎回、元のヘッダーと文書レイアウトから実験用コピーを生成する。条件分岐をインラインspanへ置換し、`@screen lg` は同等の1024px media queryに展開してからVizeへ渡した。コピーもVizeで新規コンパイルし、生成・互換処理の時間も計測に含める。元の本番ソースや基準画像は変更していない。

NuxtではVizeのコンポーネント登録より前にコピーへ差し替える。AstroではNuxt由来tsconfigのパス設定が干渉したため、移植版のコンポーネント参照は実験専用モジュールIDで固定する。これらは単純なプラグイン置換に加えて必要になった作業であり、採用判断では保守コストに含める。

Nuxtでは、リンク先の先読みで読み込まれるホームページCSSも確認が必要になった。Vizeがscoped style内のネストした `:global(html.dark)` の子セレクターを落とし、色指定を `html.dark` 全体へ漏らしていた。ホーム2コンポーネントの実験用コピーで同等の通常ancestor表現へ置換し、子要素のスコープを維持した。リンク先の先読みは無効化していない。移植3案にはこの変更を適用しない。

最終計測は、移植3案のソースを維持したまま、このNuxt専用CSS修正後に通常Nuxt・Vize Nuxtを各3回取り直した。移植3案の元の時刻は `preservedPortsFrom`、Nuxtの再計測開始は `nuxtRemeasuredAt` に記録している。全8条件を一度に取り直すには次のコマンドをオプションなしで実行する。
