# 全公開URLのSSG完走・速度検証（通常Vue／Vize）

30ファイルのVRT拡大はユーザー指示により中断し、全公開URLのSSGが完走するかを先に確認する。通常Vueの計測後、追加依頼によりVizeの4構成も検証した。この検証ではVRT・表示一致・本番移行完了を判定しない。

## 対象

現在のチェックアウトから取得した公開URL一覧を使用する。**合計1,991 URL**（ドキュメント1,365、ブログ106、固定ページ287、言語選択・転送用233）。API、アセット、ワイルドカードの旧URL転送は公開HTMLの件数に含めない。

ドキュメントにはMarkdown本文、YAML形式のステップガイド、`_dir.yml`による一覧を含む。`ja-ks`は日本語原稿を共有する。元原稿はMarkdown1,434件＋YAML156件＝1,590ファイルで、FAQ断片や非公開言語の原稿も本文処理に含める。

URLの集計根拠は[公開URL数の調査](./PUBLIC_URL_COUNT.md)、検証対象は[全件マニフェスト生成](./shared/full-pages.mjs)。一覧にある各URLについて`index.html`が存在し、空でないことを完走条件にする。SSR例外を握りつぶして空の出力を作る処理は追加していない。移植版のSSR例外検出には後述の非同期例外に関する訂正がある。

## 計測条件

- 通常Vueの4構成を各1回、順次実行。初回の規模確認であり、中央値・分散を測った結果ではない。
- Nuxtは毎回`.nuxt`と対象出力を削除。移植版は対象出力・キャッシュを削除。依存の再インストールやOSのファイルキャッシュ消去は含めない。
- 原稿処理、Vueコンパイル、SSR、HTML・クライアントJS・CSS生成、全publicアセットのコピー、出力検証を含む。
- 外側の実行時間には子プロセスの起動と全URLマニフェストの読み出しも含める。Nuxt・Astroのプリレンダー並列数は1。
- 計測中はほかのビルド・VRTを実行せず、実装と原稿のSHA-256を開始・終了時に照合する。
- チーム紹介の外部APIは実際に取得する。移植側の`useFetch`互換処理は同じURLの結果をプロセス内で共有する。外部通信の時間やOSキャッシュによる揺れは残る。

実行:

```sh
pnpm pilot:full:measure --without-vize --runs=1
```

3回の計測には`--runs=3`を指定する。個別実行は次のとおり。

```sh
HUB_PILOT_PAGES=all pnpm pilot:build baseline
HUB_PILOT_PAGES=all pnpm pilot:ssg:build ox-ported
HUB_PILOT_PAGES=all pnpm pilot:ssg:build astro
HUB_PILOT_PAGES=all pnpm pilot:ssg:build astro-ox
```

## 実装と制限

Nuxtは元のページ・コンポーネントを使い、既存の全公開URLを明示的にプリレンダーする。全件成功を判定するため`failOnError`を有効にし、実験用の出力先へ生成する。本番のルーティング・原稿は変更していない。

移植3案は、これまでの文書専用エントリーを広げ、元の通常Vueページ・レイアウト・コンポーネントも読み込む。ブログ・FAQのクエリ、翻訳、数値・日付表示、YAML内のMDC本文も接続した。ステップガイドのSSRは元のコンポーネント同様、クライアントで初期化する前の状態を出す。

**全URLのHTMLが生成できることと、元サイトの表示・操作が移行できたことは別の判定である。** この実験の固定ページ用レイアウト選択・SEO・クライアント処理は完全な移植ではない。`*.client.vue`もクライアント用チャンクにコンパイルし、SSRでは`ClientOnly`として出す。そのページ固有のクライアント動作は未検証。233件の言語エントリーは言語リンク一覧を出す段階であり、元Nuxtの自動転送処理の完全移植も未検証。これらを出力できたことだけで本番移行可能とは判定しない。

Oxを使う2案は、本文をOxで変換し、MDCコンポーネント・コンテナ・既存のコードハイライトをMDCへ渡す互換処理を使う。YAML内のMarkdownもMDCで処理する。Oxだけで全構文を処理する構成ではない。

全原稿で見つかった閉じられていないMDCコンテナは、全件検証モードだけ、そのコンテナの終端までを既存MDCへ渡す。元パーサーのEOF時の解釈を利用し、原稿を修正せず生成を継続する。この回避を30ページの厳密VRTに適用・検証したとは主張しない。

## 計測記録

最終値は[計測JSON](./results/full/timings.json)に保存する。各構成のログと内部工程の値もJSONから辿れる。2026年10月30日、Node v22.22.2 / Apple M1 Pro / darwin-arm64で実行した。

| 構成 | 全処理時間 | Nuxt比 | 公開HTML | SSR例外（当時のログ検出） |
| --- | ---: | ---: | ---: | ---: |
| Nuxt＋Content v2 | **236.77秒** | 100.0% | 1991/1,991 | 0 |
| Ox単独SSG＋移植Vueテーマ | **36.22秒** | 15.3% | 1991/1,991 | 0 |
| Astro＋既存MDC | **49.71秒** | 21.0% | 1991/1,991 | 0 |
| Astro＋Ox Content | **50.70秒** | 21.4% | 1991/1,991 | 0 |


Ox単独SSGがこの試作構成では最速だった。Astro＋OxはAstro＋MDCより0.99秒（2.0%）長く、今回の単発計測では追加による高速化は確認できなかった。少差の優劣を確定するには繰り返し計測が必要。

Ox側の全1,434 MarkdownはOx変換を通り、MDCコンポーネント・コンテナ2,724区間、コード2,434区間を既存MDCへ渡した。本文全体のMDCフォールバックは0件。YAML向けの追加Markdown文字列は全構成共通の200件。閉じ忘れコンテナの互換処理は2件だった。

計測中の実装・原稿ハッシュは一致し、4構成とも不足・空HTML・記録されたSSR例外は0件。Nuxtの出力は公開ページ以外のAPI・payloadを含めると6,721ルート。移植側はそれらのNuxt内部エンドポイントを生成しないため、その差も全処理時間に含まれる。

最終Nuxt計測中、ディスク空き容量確保のため保留したVizeの生成済み出力を削除した。ソース・原稿の変更や他ビルド・VRTの並行実行はしていないが、そのI/Oや外部APIの応答の影響は残る。直前の同じNuxtエントリーの試行では213.65秒だった。今回の値は目安として扱い、安定した中央値とはしない。

生成物は`.pilot/full/<mode>/public/`、詳細ログは同じ構成の`build.log`。計測JSONの`sample`には内部計測値も保存し、表には全構成共通の外側のプロセス経過時間（`elapsedSeconds`）を使用した。


## Vizeを追加した全件比較

| 構成 | 通常Vue | Vize 0.607.0 | Vizeの変化 | 公開HTML |
| --- | ---: | ---: | ---: | ---: |
| Nuxt＋Content v2 | 236.77秒 | **219.90秒** | -7.1% | 1,991/1,991 |
| Ox単独SSG＋移植Vueテーマ | 36.22秒 | **31.85秒** | -12.1% | 1,991/1,991 |
| Astro＋既存MDC | 49.71秒 | **51.43秒** | +3.5% | 1,991/1,991 |
| Astro＋Ox Content | 50.70秒 | **46.45秒** | -8.4% | 1,991/1,991 |

各構成1回ずつ、VRTなし。通常Vueは上記の前回計測を保持し、Vizeも順次実行した。全8構成で1,991 URLのHTML生成を確認し、採用した完走サンプルでは不足・空HTMLは0件で、当時のログ検出によるSSR例外は0件だった。Vizeの有効化は全4構成のビルドログでも確認した。SSGの試作構成の比較であり、表示・操作の完全移植を示すものではない。

VizeはCSS ModulesのSSR参照に互換処理が必要だった。NuxtだけはさらにVue RouterのCommonJS/ESM解決の修正が必要になり、修正後にNuxtを全件再計測した。移植3案はそのNuxtモジュールを読み込まないため、成功した先の計測値を保持した。本番SFC・原稿やパッケージ本体は変更していない。

Nuxtの初回失敗は227.35秒、1,765/1,991 URLだった。この値を完走時間には含めない。[初回Vize計測](./results/full/vize-timings.json)、[Nuxtの再計測](./results/full/vize-retry-timings.json)、[採用値と出典をまとめたJSON](./results/full/compiler-comparison.json)を分けて保存した。問題の詳細は[VZ-08・VZ-09](./VIZE_ISSUES.md)を参照。

今回の単発計測では、Ox単独とAstro＋OxはVizeで短縮し、Astro＋MDCは短縮しなかった。前回の通常Vueと別の時間帯の実行で、Nuxtの前回値にはディスク整理のI/Oも含む。コンパイラの効果を断定する中央値ではなく、現状の全件生成コストの目安として扱う。

再実行コマンド（通常VueのJSONは上書きしない）:

```sh
pnpm pilot:full:measure --vize-only --runs=1
# Nuxtだけの再計測
pnpm pilot:full:measure --vize-only --modes=baseline --runs=1
```

生成物を蓄積すると容量を使うため、今回のVize計測前に再生成可能な通常Vueのpublic出力・キャッシュを整理した。通常Vueの計測JSONとログは保持している。


## Profilingで判明したSSR判定の訂正

後続の[Ox単独SSGのprofiling](./PROFILING_REPORT.md)で、Vue SSRがasync setupの拒否を内部で吸収するため、例外をthrowする設定だけでは捕捉できない場合を確認した。この実行環境のネットワーク制限でチーム紹介APIの名前解決に失敗した際、HTML出力はできてもSSR処理の失敗をログ集計で見逃していた。

上記の「SSR例外0」は当時のログ検出件数で、すべての非同期SSRが成功した証明として扱うべきではなかった。過去の各試行でAPIが成功したかは記録していないため、ここでは特定しない。HTML1,991件を生成した事実と所要時間の記録は保持する。

今回、OxのSSRエントリーでVueのerrorHandlerへ集めた例外をrenderToString後に判定するよう修正した。外部APIのHTTP 200を記録した通常VueのOx単独SSGは、修正後に1,991ページを正常SSRして完走した。失敗を意図的に起こしたチーム紹介ページでも、AggregateErrorとして検出することを確認した。他の7構成はこの検出方式で再検証していない。
