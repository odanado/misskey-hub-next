# コンポーネント移植後のOx単独SSG・Astro比較

全公開1,991 URL・Vizeなし4構成の追加検証は[FULL_SSG_REPORT.md](./FULL_SSG_REPORT.md)を参照。以下は4ページの過去の検証結果。

VueコンパイラをVizeへ置き換えた追加比較は[こちら](./VIZE_REPORT.md)。以下はコンパイラ置換前の構成比較。

2026年10月30日。前回と同じ4ページを対象に、Nuxtを外す3案へ共通コンポーネントを移植した。**3案すべてで、元のNuxt基準に対して20画像のRGBA完全一致を確認した。**

## 結果

| 構成 | SSG中央値・各3回 | 実行範囲 | 最終VRT |
| --- | ---: | ---: | --- |
| 従来のNuxt / Content v2 | **41.54秒** | 41.34–43.27秒 | 16/16成功・20画像一致 |
| **Ox単独SSG＋移植Vueテーマ** | **3.76秒** | 3.74–3.88秒 | 16/16成功・20画像一致 |
| **Astro＋既存MDC** | **4.46秒** | 4.43–4.62秒 | 16/16成功・20画像一致 |
| **Astro＋Ox Content** | **4.37秒** | 4.33–4.42秒 | 16/16成功・20画像一致 |

移植版は、プロセス起動・原稿取得・Vueコンポーネントのコンパイル・SSR・クライアントJS・CSS・HTML生成・全公開アセットのコピーを含む。以前の「Ox標準テーマで約70ms」はライブラリ読込後の簡易生成時間であり、今回の値とは計測範囲が異なる。

Node 22.22.2 / Apple M1 Pro / macOS arm64。Astro 6.4.8、Vue integration 6.0.1、Vue 3.5.25、Ox 3.4.0、MDC 0.9.5、Shiki 1.29.2、UnoCSS 66.5.12、Playwright 1.58.2。

## 表示と操作の一致

4ページは日本語のノート、ハッシュタグ、プラグイン作成と、英語のノート。元のVueページ・文書レイアウト・ヘッダー・フッター・サイドバー・TOC・前後リンク・MDC注記・画像・リンク・表・AiScript表示を、共通の移植コンポーネントとしてコンパイルしている。

1440×900 / 390×844とlight/darkの組み合わせで、各構成16テストを実行した。ページ全体に加えてモバイルのメニュー・TOCを開く状態を撮影し、各20画像を比較した。PNG復号後の全RGBAバイトが一致し、マスクや許容差分は使っていない。基準画像の更新も行っていない。

SEOの主要項目、見出しID、リンク先・属性、画像alt、コード本文、JavaScript・hydrationエラー、ページ遷移も検証した。デスクトップのテーマ切り替えと再読み込み後の保存も確認した。Nuxt基準を含めて**合計64テストがすべて成功**した。

外部通信はすべて同じ条件でブロックし、ローカルフォント・画像とhydrationを待っている。元のGoogle Fonts参照も移植しているが、外部フォントの実取得や他ブラウザーでの表示は、このVRTでは検証していない。

## 実装の違い

**Ox単独SSG**では、元のVueコンポーネントをViteでコンパイルし、各ページを新たにSSRする。その結果をOxのカスタムテーマに渡し、Ox自身のSSGがルートとHTMLを出力する。原稿由来のメタデータからサイドバー・前後リンクも生成する。既存Nuxtの生成HTML・CSSや基準画像を移植版の入力には使っていない。

**Astro版**は、`.astro` の `getStaticPaths()` でルートを列挙し、公式Vue integrationによるSSRと `client:load` で同じVueコンポーネントを描画する。本文は表示互換性のために既存MDC / unifiedを直接使う。Astro標準Markdownコンパイラーの性能を示す結果ではない。

**Astro＋Ox版**は、Astro版の表示とSSGを維持し、メタデータ取得とMarkdown本文処理をOxのRust APIへ置き換える。Astro版と共通のパイプラインを使うので、本文処理の追加効果を比較できる。

新構成ではNuxtのSSG・ルーター・Contentサーバーを起動しない。元のMDC・Prose表示ライブラリと純粋なパスメタデータ処理は再利用している。ページ遷移はMPAとし、NuxtのSPAルーターや遷移中のNProgressは移植対象外とした。

## なぜ短縮できたか

メタデータの取得対象は従来と同じ全1,590ファイルだが、新構成では本文をパースする対象を4ページに限定した。Nuxt Contentの全件本文ASTキャッシュ生成を取り除き、サイドバー・前後リンクをメタデータから生成している。従来構成の全件キャッシュ生成には今回も約17.6–18.1秒かかっていた。

さらに、新構成は4ページ用のアプリとしてコンパイルする。Nuxt基準は4ページをプリレンダーする設定でも、既存サイト全体のルートとクライアントモジュールをビルドしている。この差も短縮に含まれる。**今回の約3.8–4.5秒を、そのまま全サイト移行後のSSG時間として扱うことはできない。**

## Astro＋Oxは有効か

今回の中央値では **4.46秒 → 4.37秒、約0.09秒・2.0%の短縮**だった。追加効果は確認できたが、4ページでは小さい。

| 原稿処理の内訳・中央値 | Astro＋MDC | Astro＋Ox |
| --- | ---: | ---: |
| 全件メタデータ取得・整理 | 0.250秒 | 0.212秒 |
| 対象本文＋ナビゲーション生成 | 0.080秒 | 0.063秒 |

この部分の差は合計約0.055秒。全体の大部分はコンパイル・アセット処理・SSG基盤側にある。サンプル数も3回なので、約2%の差を大規模な高速化の根拠にはしない。

Astro＋Oxでは、MDC互換AST、注記、相対リンク、目次、英文補正、画像alt、既存Shikiとの接続を保守する必要がある。今回の結果では、追加の互換処理を導入する優先度は低い。本文変換数を増やした検証で処理時間が支配的になった場合に、併用の価値を再評価するのが妥当。

## 提案

**SSG時間を最優先する場合、今回の4ページではOx単独SSGが最速**だった。一方で、Vueの非同期SSR、hydrate用データ、クライアントエントリー、アセットの接続を自前で持つ実装になる。

**今後のページ移行・保守を含めるなら、Astro＋既存MDCを第一候補として提案する。** 今回も約4.46秒まで短縮でき、ルーティング・静的出力・Vue islandのhydrateをAstroの仕組みに任せられる。本文パーサーの互換処理を増やす前に、残りのページ種別を移植して全サイトの時間を測る方が判断しやすい。

Astro＋Oxの導入は、その全体計測で本文処理のコストを確認してから判断する。現在の結果では、単独Astroからの改善は約0.09秒にとどまる。

## 残る移行範囲

この検証はパイロット4ページの静止表示と確認した操作の一致を示す。本文の全MDC構文、独自frontmatter、YAMLステップガイド、ディレクトリ索引、ブログ、全言語、全ルート・旧URLリダイレクト、文書以外のインタラクティブページは未移植・未検証。

実装では、既存CSSの適用順、SVGのVue解釈、Shiki CSS抽出時のhydrationと余白、文書ごとの見出しID状態、Astroのビルド環境に対する既存UnoCSSの対応が必要になった。これらの詳細は[実装・再現手順](./README.md)に記載した。既存の英語canonicalの二重スラッシュも、比較時には維持している。

本番のVueページ・原稿・デプロイフローは移行していない。元の依存定義とパッケージ解決結果を維持し、実験用の開発依存を追加した。CI設定は追加したが、GitHub Actions自体の実行結果はこのローカル検証には含めない。
